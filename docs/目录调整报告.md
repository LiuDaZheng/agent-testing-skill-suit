## 🎯 调整原因

### 1. 多项目支持

**问题**: 如果所有项目都在 `workspace-skilldev/` 下：
- ❌ 目录会变得越来越混乱
- ❌ 项目间边界不清晰
- ❌ 难以管理多个项目

**解决**: 使用 `projects/` 目录：
- ✅ 每个项目独立目录
- ✅ 清晰的项目边界
- ✅ 易于扩展

### 2. 职责分离

| 目录 | 用途 |
|------|------|
| `projects/` | 所有项目源码 |
| `workspace-skilldev/` | Agent 工作区配置 |
| `skills/` | 共享 Skill（已验收） |

### 3. 最佳实践

符合标准项目组织：
- ✅ 项目隔离
- ✅ 资源共享
- ✅ 清晰命名

## 📝 多项目管理规范

### 项目命名

- ✅ 使用 kebab-case
- ✅ 描述性名称
- ✅ 避免特殊字符

**示例**:
- ✅ `Agent-Testing-Skill-Suit`
- ✅ `feishu-automation`
- ❌ `test skill` (有空格)

### 项目创建流程

```bash
# 1. 创建项目目录
mkdir -p ~/.openclaw/projects/<project-name>

# 2. 初始化项目结构
cd ~/.openclaw/projects/<project-name>
mkdir -p docs src/skills tests config scripts logs references

# 3. 创建项目文档
cat > README.md << 'EOF'
# Project Name
项目概述...
EOF
```

### 项目验收流程

```
开发 → src/skills/
  ↓
测试 → tests/
  ↓
验收 → 项目验收委员会
  ↓
部署 → ~/.openclaw/skills/
```

# 2. 复制项目模板

       ~/.openclaw/projects/<new-project>/

### 项目归档

项目完成后：
```bash
# 1. 部署已验收 Skill
cp -r src/skills/<skill-name> ~/.openclaw/skills/

# 2. 归档项目（可选）
mv ~/.openclaw/projects/<project-name> \
   ~/.openclaw/projects-archive/
```
