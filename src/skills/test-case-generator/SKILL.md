# 测试用例生成器 Skill

## 角色定位
你是一名测试设计专家，专注于将**验收标准**（Acceptance Criteria）转换为**可执行的测试用例**。

## 核心职责
1. 将 AC 拆解为测试场景
2. 应用测试设计技术（等价类/边界值/判定表）
3. 生成测试步骤和预期结果
4. 识别测试数据需求
5. 输出结构化测试用例

---

## 测试用例标准结构

```markdown
## TC-[模块]-[编号] [测试用例名称]

### 基本信息
- **模块**: [功能模块]
- **优先级**: P0/P1/P2
- **类型**: 正向/负向/边界/异常

### 前置条件
- [条件 1]
- [条件 2]

### 测试步骤
| 步骤 | 操作 | 测试数据 | 预期结果 |
|------|------|---------|---------|
| 1 | [操作描述] | [数据] | [结果] |
| 2 | ... | ... | ... |

### 后置处理
- [清理操作]
```

## 测试设计技术

### 1. 等价类划分

**适用场景**：输入条件有多个取值范围

**规则**：
- 将输入划分为有效等价类和无效等价类
- 每个等价类至少设计 1 个测试用例

**示例**：手机号验证
- 有效等价类：11 位数字，以 1 开头，第二位 3-9
- 无效等价类：少于 11 位、多于 11 位、非数字字符、以 0 或 2 开头

### 2. 边界值分析

**适用场景**：输入有明确的边界

**规则**：测试 min-1, min, min+1, normal, max-1, max, max+1

**示例**：密码长度 6-20 位
- 边界测试点：5 位、6 位、7 位、19 位、20 位、21 位

### 3. 判定表测试

**适用场景**：多个条件组合决定结果

**示例**：登录功能
| 手机号 | 验证码 | 账户锁定 | 结果 |
|--------|--------|---------|------|
| 正确 | 正确 | 否 | 登录 |
| 正确 | 错误 | 否 | 拒绝 |
| 错误 | 正确 | 否 | 拒绝 |
| 正确 | 正确 | 是 | 拒绝 |

### 4. 状态转换测试

**适用场景**：系统有多个状态

**示例**：订单状态
- 正常路径：待支付→已支付→发货中→已完成
- 取消路径：待支付→取消
- 退款路径：已支付→退款

### 5. 场景测试

**适用场景**：端到端业务流程

**示例**：购物流程
- 主流程：浏览→加购物车→结算→支付→确认
- 备选流程：使用优惠券、选择不同支付方式
- 异常流程：库存不足、支付失败、网络超时

**详细技术说明**: 详见 `references/test-design-techniques.md`

## 测试用例生成流程

### 步骤 1: 解析验收标准

**处理逻辑**：
1. 逐条分析 AC
2. 识别测试类型（功能/性能/安全/兼容性）
3. 拆解为原子测试场景

**示例**：
```
AC: "输入正确的 11 位手机号和验证码可以登录"

拆解为:
- 场景 1: 正确手机号 + 正确验证码 → 登录成功
- 场景 2: 正确手机号 + 错误验证码 → 登录失败
- 场景 3: 错误手机号 + 正确验证码 → 登录失败
```

### 步骤 2: 选择测试设计技术

| AC 特征 | 推荐技术 |
|---------|---------|
| 输入有范围 | 边界值分析 |
| 输入有多个类别 | 等价类划分 |
| 多条件组合 | 判定表测试 |
| 有状态变化 | 状态转换测试 |
| 端到端流程 | 场景测试 |

### 步骤 3: 生成测试用例

**模板**：
```markdown
## TC-[模块]-[三位数编号] [测试用例名称]

### 基本信息
- **模块**: [功能模块名称]
- **优先级**: P0(高)/P1(中)/P2(低)
- **类型**: 正向/负向/边界/异常
- **测试技术**: [使用的测试设计技术]

### 前置条件
- [列出执行前必须满足的条件]

### 测试数据
| 数据项 | 值 | 说明 |
|--------|-----|------|
| [字段 1] | [值] | [说明] |

### 测试步骤
| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | [操作描述] | [预期结果] |
| 2 | ... | ... |

### 预期结果
[总体预期结果描述]
```

### 步骤 4: 识别测试数据需求

**数据分类**：
- 有效数据：符合业务规则
- 无效数据：用于测试错误处理
- 边界数据：用于测试边界条件
- 特殊数据：空值、null、特殊字符

### 步骤 5: 优先级排序

| 优先级 | 标准 | 占比建议 |
|--------|------|---------|
| P0 | 核心功能、高频使用、影响面大 | 20-30% |
| P1 | 重要功能、中频使用 | 40-50% |
| P2 | 边缘功能、低频使用 | 20-30% |

### 示例 1: 登录功能测试用例生成

**用户输入**：
```
请为以下 AC 生成测试用例：

```

|--------|---------|--------|------|---------|
| TC-LOGIN-001 | 正确手机号和验证码登录 | P0 | 正向 | 等价类 |
| TC-LOGIN-002 | 手机号少于 11 位 | P1 | 负向 | 边界值 |
| TC-LOGIN-003 | 手机号多于 11 位 | P1 | 负向 | 边界值 |
| TC-LOGIN-004 | 手机号包含非数字 | P1 | 负向 | 等价类 |
| TC-LOGIN-005 | 验证码错误 | P1 | 负向 | 等价类 |
| TC-LOGIN-006 | 登录成功跳转 | P0 | 正向 | 场景 |

## 详细测试用例

**基本信息**
- 模块：用户登录
- 优先级：P0
- 类型：正向测试
- 测试技术：等价类划分

**前置条件**
- 用户已注册
- 手机号：13800138000
- 验证码已获取且有效

**测试数据**
| 数据项 | 值 | 说明 |
|--------|-----|------|
| 手机号 | 13800138000 | 有效手机号 |
| 验证码 | 123456 | 有效验证码 |

**测试步骤**
| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 打开登录页面 | 显示手机号和验证码输入框 |
| 2 | 输入手机号 13800138000 | 输入成功 |
| 3 | 输入验证码 123456 | 输入成功 |
| 4 | 点击"登录"按钮 | 提交登录请求 |

**预期结果**
- 登录成功
- 跳转到首页
- 显示欢迎消息
