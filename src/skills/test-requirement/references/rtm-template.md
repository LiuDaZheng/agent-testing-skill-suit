# 需求跟踪矩阵（RTM）模板

## 模板结构

```markdown
| 需求 ID | 需求描述 | 需求类型 | 优先级 | 测试条件 ID | 测试用例 ID | 测试状态 | 备注 |
|--------|----------|----------|--------|-------------|-------------|----------|------|
| REQ-001 | 用户登录功能 | 功能 | High | COND-001 | TC-001~010 | Pending | |
| REQ-002 | 响应时间<2s | 非功能 | High | COND-002 | TC-PERF-001 | Pending | 性能测试 |
```

## 字段说明

| 字段 | 说明 | 示例值 |
|------|------|--------|
| 需求 ID | 唯一标识符 | REQ-001, REQ-002 |
| 需求描述 | 需求内容摘要 | 用户登录功能 |
| 需求类型 | 功能/非功能/接口/约束 | 功能、非功能 |
| 优先级 | High/Medium/Low | High |
| 测试条件 ID | 测试条件标识 | COND-001 |
| 测试用例 ID | 关联的测试用例 | TC-001~010 |
| 测试状态 | Pending/In Progress/Completed | Pending |
| 备注 | 补充说明 | 性能测试 |

## 需求类型分类

### 功能需求
- 业务功能（登录、注册、支付等）
- 数据处理（增删改查）
- 业务流程

### 非功能需求
- 性能（响应时间、吞吐量）
- 安全性（认证、授权、加密）
- 可用性（易用性、可访问性）
- 兼容性（浏览器、设备、OS）
- 可靠性（MTBF、容错）

### 接口需求
- API 接口规范
- 数据格式（JSON/XML）
- 协议（HTTP/HTTPS、WebSocket）

### 约束条件
- 技术栈限制
- 法律法规合规
- 第三方依赖

## 使用指南

1. **从需求文档提取**：逐条阅读需求，分配唯一 ID
2. **分类标注**：标记每个需求的类型和优先级
3. **映射测试条件**：为每个需求定义"测什么"
4. **关联测试用例**：将测试条件细化为具体用例
5. **跟踪状态**：执行过程中更新测试状态
