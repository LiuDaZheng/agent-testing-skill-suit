# ISTQB 状态转换测试技术参考

## 官方定义 (ISTQB CTFL Syllabus)

**状态转换测试 (State Transition Testing)**: 一种黑盒测试技术，测试用例设计用于执行有效的状态转换和无效的转换。

### 测试基础
- **有限状态机 (FSM)**: 系统在任何时刻都处于有限状态之一
- **转换规则**: 当前状态 + 事件 → 下一状态 + 动作

## 覆盖类型

### 1. 状态覆盖 (State Coverage)
测试所有可达状态至少一次。
```
覆盖率 = 测试过的状态数 / 总状态数 × 100%
```

### 2. 转换覆盖 (Transition Coverage / 0-switch)
测试所有有效转换至少一次。
```
覆盖率 = 测试过的转换数 / 总转换数 × 100%
```

### 3. n-switch 覆盖
测试所有长度为 n+1 的转换序列。
- **1-switch**: 测试所有长度为 2 的序列
- **2-switch**: 测试所有长度为 3 的序列

### 4. 无效转换覆盖
测试所有不允许的转换被正确拒绝。

## 状态图符号

```
     ┌─────────┐
     │  状态   │  ← 圆形或圆角矩形
     └─────────┘
          ↑
          │ 箭头表示转换
     [事件/条件]
     [动作]
```

## 测试用例设计步骤

1. **识别状态**: 从需求文档中提取所有系统状态
2. **识别事件**: 确定触发状态变化的所有输入
3. **绘制状态图**: 可视化状态和转换关系
4. **创建状态表**: 表格形式记录所有转换
5. **设计测试用例**: 
   - 覆盖所有状态
   - 覆盖所有有效转换
   - 覆盖关键转换序列
   - 测试无效转换
6. **执行测试**: 按测试用例执行并记录结果
7. **分析覆盖**: 计算覆盖率，补充遗漏测试

## Chow 测试方法

### 1-切换覆盖 (1-switch coverage)
测试所有可能的两转换序列。

**示例**: 如果系统有转换 A→B 和 B→C，则测试序列 A→B→C。

### 应用条件
- 系统状态依赖于历史
- 需要验证状态记忆
- 关键安全系统

## 常见错误模式

1. **遗漏状态**: 未识别所有可能状态
2. **死锁**: 状态没有出口转换
3. **不可达状态**: 没有转换能到达该状态
4. **歧义转换**: 同一状态 + 事件导致多个可能下一状态
5. **未处理事件**: 某状态下未定义某些事件的处理
