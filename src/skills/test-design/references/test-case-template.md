# 测试用例模板

## 标准模板

```markdown
## TC-[模块]-[编号]: [测试目的]

### 基本信息
| 字段 | 值 |
|------|-----|
| 测试用例 ID | TC-LOGIN-001 |
| 测试模块 | 用户登录 |
| 需求 ID | REQ-001 |
| 优先级 | High |
| 设计者 | 张三 |
| 设计日期 | 2024-01-05 |

### 前置条件
- [列出执行前必须满足的条件]
- 示例：用户已注册，手机号：13800138000
- 示例：应用已启动，处于登录页面

### 测试步骤
| 步骤 | 操作 | 测试数据 |
|------|------|----------|
| 1 | 输入手机号 | 13800138000 |
| 2 | 输入密码 | Test@1234 |
| 3 | 点击"登录"按钮 | - |

### 预期结果
- [明确的可验证结果]
- 示例：登录成功，跳转到首页
- 示例：显示欢迎消息："欢迎，[用户名]"

### 实际结果
- [执行时填写]

### 执行状态
- [ ] Pass
- [ ] Fail
- [ ] Blocked
- [ ] Skipped

### 优先级
[High/Medium/Low]

### 自动化标记
- 可自动化：[Yes/No]
- 自动化脚本 ID：AUTO-LOGIN-001（如适用）

### 备注
- [补充说明、特殊注意事项]
```

## 自动化测试用例模板

```markdown
## AUTO-[模块]-[编号]: [测试目的]

### 脚本信息
| 字段 | 值 |
|------|-----|
| 脚本 ID | AUTO-LOGIN-001 |
| 对应手工用例 | TC-LOGIN-001 |
| 自动化框架 | Selenium/Pytest |
| 执行环境 | Chrome, Windows 10 |
| 执行时间 | ~30 秒 |

### 脚本代码
```python
def test_valid_login():
    driver.get("/login")
    driver.find_element("phone").send_keys("13800138000")
    driver.find_element("password").send_keys("Test@1234")
    driver.find_element("submit").click()
    assert "首页" in driver.title
```

### 断言检查
- [ ] 页面跳转正确
- [ ] 欢迎消息显示
- [ ] 用户信息正确

### 维护记录

```

## 测试用例编写最佳实践

### DO（推荐）
- ✅ 每个用例只测试一个场景
- ✅ 步骤清晰、可重复执行
- ✅ 预期结果明确、可验证
- ✅ 使用具体的测试数据
- ✅ 标注优先级和自动化标记

### DON'T（避免）
- ❌ 一个用例测试多个场景
- ❌ 步骤模糊（如"正常操作"）
- ❌ 预期结果不明确（如"系统正常"）
- ❌ 使用模糊数据（如"某个用户"）
- ❌ 缺少前置条件
