# ISTQB 探索式测试技术参考

## 官方定义 (ISTQB CTFL/CTFL-AT)

**探索式测试 (Exploratory Testing)**: 一种测试方法，测试人员同时设计、执行和记录测试，依靠测试人员的技能和对系统的理解。

### 核心特点
- 测试设计和执行同时进行
- 依赖测试人员的创造力和经验
- 适应性强，适合敏捷环境
- 发现意外缺陷能力强

## 会话管理 (SBTM)

### 会话结构

```
┌─────────────────────────────────────────┐
│          探索式测试会话                  │
├─────────────────────────────────────────┤
│  准备阶段 (10%)                          │
│  - 理解章程                              │
│  - 准备测试数据                          │
│  - 设置环境                              │
├─────────────────────────────────────────┤
│  执行阶段 (70%)                          │
│  - 按章程探索                            │
│  - 记录发现                              │
│  - 提交 bug                             │
├─────────────────────────────────────────┤
│  总结阶段 (20%)                          │
│  - 整理笔记                              │
│  - 生成报告                              │
│  - 规划后续                              │
└─────────────────────────────────────────┘
```

### 时间盒建议

| 会话类型 | 建议时长 | 适用场景 |
|---------|---------|---------|
| 快速探索 | 30-45 分钟 | 小功能、bug 验证 |
| 标准会话 | 60-90 分钟 | 功能模块、用户故事 |
| 深度探索 | 120 分钟 | 复杂功能、系统集成 |

## 测试章程设计

### 好章程的特征

✅ **具体但不限制**: 指明方向但不规定步骤
✅ **可执行**: 在时间盒内可完成
✅ **有价值**: 针对风险区域或重要功能
✅ **可验证**: 能明确是否完成

### 章程公式

```
探索 [什么]
使用 [什么方法/工具/启发法]
以发现 [什么类型的信息]
```

### 章程示例

```
好:
- "探索搜索功能，使用特殊字符和边界值，以发现输入验证问题"
- "探索支付流程，使用中断测试，以发现状态同步问题"

不好:
- "测试搜索" (太宽泛)
- "输入'admin'到搜索框，点击搜索，验证结果" (太具体)
```

## 测试启发法详解

### SFDPOT 模型

```
S - Structure (结构)
  - 产品由哪些组件组成
  - 组件间如何连接
  - 物理/逻辑架构

F - Function (功能)
  - 产品能做什么
  - 每个功能的行为
  - 功能间交互

D - Data (数据)
  - 输入数据
  - 输出数据
  - 持久化数据
  - 数据流

P - Platform (平台)
  - 操作系统
  - 浏览器/设备
  - 外部依赖
  - 配置项

O - Operations (操作)
  - 用户如何使用
  - 使用场景
  - 用户角色

T - Time (时间)
  - 时序问题
  - 并发问题
  - 性能随时间变化
  - 数据过期
```

### CRUD 启发法

```
Create (创建)
- 创建最小有效数据
- 创建最大允许数据
- 创建边界数据
- 创建无效数据

Read (读取)
- 查看单个项目
- 查看列表
- 搜索和过滤
- 排序

Update (更新)
- 修改所有字段
- 修改部分字段
- 并发修改
- 修改权限验证

Delete (删除)
- 删除单个
- 批量删除
- 删除有依赖数据
- 删除后验证
```

### 测试游览类型

| 游览 | 描述 | 适用 |
|------|------|------|
| 地标游览 | 访问所有主要功能 | 新功能熟悉 |
| 导游游览 | 跟随文档/指南 | 验证文档准确性 |
| 糟糕邻居 | 测试问题高发区 | 回归测试 |
| 反社会 | 尝试破坏系统 | 稳定性测试 |
| 博物馆 | 测试老旧代码 | 技术债务评估 |
| 超级模特 | 关注 UI/UX | 视觉测试 |
| 强迫症 | 重复操作 | 稳定性/内存泄漏 |
| 背包客 | 深度探索某功能 | 专项测试 |

## 记录方法

### 笔记内容

```
- 时间戳
- 探索区域
- 测试思路
- 观察结果
- 问题/疑问
- bug 引用
```

### 记录工具

- 文本笔记：快速记录想法
- 截图：视觉问题
- 录屏：复杂交互
- 日志：技术细节

## 覆盖率评估

### 覆盖维度

```
功能覆盖:
- 已探索的功能模块
- 未探索的功能模块

场景覆盖:
- 正常场景
- 异常场景
- 边界场景

数据覆盖:
- 数据类型
- 数据范围
- 数据组合

平台覆盖:
- 浏览器
- 设备
- 操作系统
```

### 覆盖可视化

```
功能地图:
[首页] ✅  [搜索] ✅  [详情] ✅
[购物车] ✅  [结算] ✅  [支付] ⚠️
[订单] ⚠️  [账户] ❌  [设置] ❌

✅ 完成  ⚠️ 部分  ❌ 未开始
```

## 质量评估

### 会话质量指标

- **Bug 发现率**: Bug 数 / 会话时长
- **覆盖密度**: 覆盖区域 / 计划区域
- **发现多样性**: 不同类型 bug 的数量
- **章程完成度**: 完成章程数 / 计划章程数

### 探索深度评估

```
Level 1: 表面探索
  - 正常流程
  - 明显输入

Level 2: 中等深度
  - 边界值
  - 常见异常

Level 3: 深度探索
  - 复杂组合
  - 并发场景
  - 极端条件
```
