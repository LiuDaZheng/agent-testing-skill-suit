# ISTQB 决策表测试技术参考

## 官方定义 (ISTQB CTFL Syllabus)

**决策表测试 (Decision Table Testing)**: 一种黑盒测试技术，测试用例设计用于执行输入条件的组合。

### 适用标准
- 多个条件组合影响业务逻辑
- 需要系统化处理条件组合
- 业务规则明确可表格化

## 决策表组成

### 四个象限

```
┌──────────────────┬──────────────────┐
│   条件桩         │    条件项        │
│ (Condition Stub) │ (Condition Entry)│
├──────────────────┼──────────────────┤
│   动作桩         │    动作项        │
│ (Action Stub)    │ (Action Entry)   │
└──────────────────┴──────────────────┘
         ↑                  ↑
     条件列表          规则列
```

### 详细说明

**条件桩**: 列出所有输入条件
- 通常是布尔值 (Y/N)
- 也可能是多值条件

**动作桩**: 列出所有可能输出
- 系统响应
- 状态变化
- 计算结果

**条件项**: 每个规则下条件的取值
- Y/N/-(无关)

**动作项**: 每个规则下执行的动作
- X(执行)/空白 (不执行)

## 决策表类型

### 1. 有限条目决策表
所有条件都是布尔值 (Y/N)。

### 2. 扩展条目决策表
条件可以有多个值。

```
示例：支付方式
- 信用卡
- 借记卡
- 支付宝
- 微信支付
```

## 构建步骤详解

### Step 1: 识别条件
```
从需求文档提取:
- if 语句的条件
- 业务规则的前提条件
- 输入验证规则
```

### Step 2: 识别动作
```
从需求文档提取:
- then 语句的结果
- 系统响应
- 输出消息
```

### Step 3: 计算规则数
```
公式: 规则数 = ∏(条件 i 的取值数)

示例:
- 3 个布尔条件: 2^3 = 8 规则
- 1 个三值条件 + 2 个布尔: 3 × 2 × 2 = 12 规则
```

### Step 4: 填充规则
```
方法 1: 二进制递增
  R1: N N N
  R2: N N Y
  R3: N Y N
  R4: N Y Y
  R5: Y N N
  R6: Y N Y
  R7: Y Y N
  R8: Y Y Y

方法 2: 业务规则驱动
  只填充实际存在的业务规则
```

### Step 5: 简化
```
识别可合并的规则:
R1: Y Y - → A1
R2: Y N - → A1

合并为:
R1-2: Y - - → A1
```

### Step 6: 验证
```
检查:
- 完整性：所有规则都覆盖？
- 一致性：无矛盾规则？
- 可达性：所有规则都可能触发？
```

## 覆盖率类型

### 1. 规则覆盖 (Rule Coverage)
```
覆盖率 = 测试过的规则数 / 总规则数 × 100%

目标：100%
```

### 2. 条件覆盖 (Condition Coverage)
```
覆盖率 = 测试过的条件取值数 / 总条件取值数 × 100%

确保每个条件的每个取值都测试过
```

### 3. 动作覆盖 (Action Coverage)
```
覆盖率 = 测试过的动作数 / 总动作数 × 100%

确保每个动作都至少执行一次
```

|---------|----|----|----|----|----|----|----|----|
| **条件** |    |    |    |    |    |    |    |    |
| C1: 条件 1 | Y  | Y  | Y  | Y  | N  | N  | N  | N  |
| C2: 条件 2 | Y  | Y  | N  | N  | Y  | Y  | N  | N  |

## 测试用例设计

### 从决策表生成测试用例

```gherkin
# 规则 R1 的测试用例
Scenario: R1 - 条件全为真
  Given 条件 1 为真
  And 条件 2 为真
  And 条件 3 为真
  When 执行操作
  Then 动作 1 应执行
  And 动作 2 不应执行
  And 动作 3 不应执行
```

### 测试数据设计

```yaml
测试用例：TC-R1
输入:
  条件 1: true
  条件 2: true
  条件 3: true
预期输出:
  动作 1: executed
  动作 2: not_executed
  动作 3: not_executed
实际结果: ""
状态: ""
```

## 复杂情况处理

### 1. 条件依赖
```
当条件 C2 依赖于 C1 时:
- C1=N 时，C2 无意义 → 使用"-"
- 只在 C1=Y 的列中定义 C2
```

### 2. 互斥条件
```
当条件 C1 和 C2 互斥时:
- C1=Y 且 C2=Y 的规则不可能出现
- 标记为"不可能"或省略
```

### 3. 默认规则
```
添加"ELSE"规则处理未覆盖情况:
- 所有其他规则不匹配时
- 通常对应错误处理
```

## 质量检查清单

- [ ] 所有条件独立且明确
- [ ] 所有动作互斥或可组合
- [ ] 规则数正确 (2^n 或简化后)
- [ ] 无矛盾规则
- [ ] 无遗漏规则
- [ ] 已处理不可能组合
- [ ] 已添加默认规则
